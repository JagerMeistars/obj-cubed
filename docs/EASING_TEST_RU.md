# obj³ — внутриигровой тест easing-кривых

Набор для ручной проверки шести режимов сглаживания анимации вершин (поле
**Плавность / Easing** в диалоге экспорта плагина). Цель — глазами убедиться,
что каждый режим даёт своё характерное движение, и что старые паки без
easing не сломались.

Все пути ниже — от корня `C:\Users\konst\AppData\Roaming\.minecraft\resourcepacks`
(далее `…\resourcepacks`). Плагин: `…\resourcepacks\obj-cubed\objcubed.js`.

---

## 1. Тестовая модель в Blockbench за 5 минут

1. **Формат.** File → New → Generic Model (или Free Model). Единица — блок.
2. **Куб.** Add Cube. Размер 16×16×16 (один блок). Позиция по центру, origin
   куба в его низу (Y = 0), чтобы подъём читался.
3. **Текстура.** Любая одноцветная 16×16 (Paint → новая текстура), назначить на
   куб. Для теста easing текстура не важна — важна геометрия кадров.
4. **Анимация подъёма.** Animate → New Animation, назови `rise`.
   - Length: **20 кадров** при 20 fps → 1.0 s (поле Length = `1.0`).
   - Keyframe на 0.0 s: Position Y = `0`.
   - Keyframe на 1.0 s: Position Y = `2` (подъём на 2 блока = 32 px).
   - Между кадрами Blockbench поставит свою интерполяцию — она нас не волнует:
     obj³ запекает **позы по кадрам** (per-frame вершины) и уже поверх них
     накладывает свою easing-кривую при воспроизведении в игре.
5. **Держи ровно 20 дискретных кадров.** obj³ семплирует анимацию по кадрам;
   20 кадров дают заметную «лестницу» в режиме hold и гладкость в остальных.

### Экспорт шести вариантов

Открой диалог экспорта obj³. В нём есть селектор:

- Точное имя поля в UI: **`Плавность`** (англ. локаль — **`Easing`**).
  В разметке это `<select v-model="easing">`, якорь тура `.oc-tour-easing`,
  метка берётся из ключа `lbl_easing` (`objcubed.js`, строки 5710–5719).

Пункты выпадающего списка и их числовые значения (`opt_*`):

| easing | Пункт списка (RU / EN)      | Что проверяем |
|:------:|-----------------------------|---------------|
| 0      | Нет (удержание) / None (hold) | ступени       |
| 1      | Линейная / Linear           | равномерно    |
| 2      | Кубическая / Cubic (in-out) | S-кривая (in-out) |
| 3      | Catmull-Rom                 | плавные дуги через кадры |
| 4      | Ease-In (квадрат) / Ease-In (quad)  | разгон  |
| 5      | Ease-Out (квадрат) / Ease-Out (quad) | торможение |

Экспортируй модель **6 раз**, каждый раз меняя только «Плавность», и давай
файлам/имени модели (`cmdName`) разное имя, чтобы give-команды не совпали:

- `rise_hold`   → easing = 0
- `rise_linear` → easing = 1
- `rise_inout`  → easing = 2
- `rise_catmull`→ easing = 3
- `rise_easein` → easing = 4
- `rise_easeout`→ easing = 5

Экспортируй все шесть в один и тот же ресурспак-каталог (`resourcePackDir`),
чтобы предметы жили рядом и различались только строкой custom_model_data.

Примечание: easing — это 4-битный индекс НА АНИМАЦИЮ, упакованный в служебные
биты PNG-текстуры данных (`objcubed.js` ~2904–2912). Значение выбирается один раз
на экспорт и применяется ко всей анимации.

## 2. Выдача и спавн шести вариантов рядом

### Из чего состоит выдача

Плагин при экспорте пишет give-хелпер:
`assets/minecraft/items/<baseItem>_give.txt` (`objcubed.js` 3660–3670).
Содержимое файла — ровно одна команда:

```
give @s minecraft:<baseItem>[minecraft:custom_model_data={strings:["<modelName>"]}]
```

где:
- `<baseItem>` — базовый предмет из поля `baseItem` (по умолчанию `iron_ingot`);
- `<modelName>` — имя модели: `cmdName` (или имя проекта), приведённое к
  `[a-z0-9_]` в нижнем регистре (`objcubed.js` 3540).

Важно: имя файла берётся от `baseItem`, а НЕ от модели. Поэтому, если все шесть
экспортов используют один и тот же базовый предмет, они перезапишут один и тот же
`<baseItem>_give.txt` — в нём останется команда только для последнего экспорта.
Чтобы получить шесть команд рядом, выбери один из вариантов:

- **Проще:** дай каждому экспорту свой `baseItem`
  (например `iron_ingot`, `gold_ingot`, `copper_ingot`, `diamond`, `emerald`,
  `netherite_ingot`) — тогда получишь шесть отдельных `*_give.txt`.
- **Или:** после каждого экспорта скопируй строку из `<baseItem>_give.txt` в
  свой блокнот, меняя только `strings:["…"]` на нужное имя модели.

Итоговые шесть команд (при общем базовом предмете `iron_ingot`) выглядят так —
их можно вставить в командный блок или чат по очереди:

```
give @s minecraft:iron_ingot[minecraft:custom_model_data={strings:["rise_hold"]}]
give @s minecraft:iron_ingot[minecraft:custom_model_data={strings:["rise_linear"]}]
give @s minecraft:iron_ingot[minecraft:custom_model_data={strings:["rise_inout"]}]
give @s minecraft:iron_ingot[minecraft:custom_model_data={strings:["rise_catmull"]}]
give @s minecraft:iron_ingot[minecraft:custom_model_data={strings:["rise_easein"]}]
give @s minecraft:iron_ingot[minecraft:custom_model_data={strings:["rise_easeout"]}]
```

### Спавн рядом

Модель показывается на предмете в item_display / item frame. Расставь шесть
предметов в ряд, чтобы сравнивать одновременно. Пример — шесть item_display с
одинаковой позой в линию по X (запускать по одному, координаты меняем на +1.5):

```
summon item_display ~ ~1 ~ {item:{id:"minecraft:iron_ingot",count:1,components:{"minecraft:custom_model_data":{strings:["rise_hold"]}}}}
summon item_display ~1.5 ~1 ~ {item:{id:"minecraft:iron_ingot",count:1,components:{"minecraft:custom_model_data":{strings:["rise_linear"]}}}}
summon item_display ~3 ~1 ~ {item:{id:"minecraft:iron_ingot",count:1,components:{"minecraft:custom_model_data":{strings:["rise_inout"]}}}}
summon item_display ~4.5 ~1 ~ {item:{id:"minecraft:iron_ingot",count:1,components:{"minecraft:custom_model_data":{strings:["rise_catmull"]}}}}
summon item_display ~6 ~1 ~ {item:{id:"minecraft:iron_ingot",count:1,components:{"minecraft:custom_model_data":{strings:["rise_easein"]}}}}
summon item_display ~7.5 ~1 ~ {item:{id:"minecraft:iron_ingot",count:1,components:{"minecraft:custom_model_data":{strings:["rise_easeout"]}}}}
```

Если для варианта включён датапак (`generateDatapack`), у него есть свои функции
`<namespace>:<model>/summon`, `…/play`, `…/play_once` (см. сгенерированный
`README.txt` датапака, `objcubed.js` ~4130–4145). Для item_display спавн —
`function <ns>:<model>/summon`, запуск анимации — `…/play`.

Анимация обычно самозапускается (autoplay), если он не отключён при экспорте;
иначе запусти `…/play` один раз на каждую сущность.

## 3. Что должно быть видно

Все шесть кубов проходят один и тот же путь: подъём 0 → 2 блока за 20 кадров.
Различие — только в форме движения между кадрами:

- **hold (0)** — ступени: куб телепортируется по кадрам, видна «лестница»,
  скачки без промежуточного смещения.
- **linear (1)** — равномерно: постоянная скорость от старта до конца, без
  разгона и торможения.
- **ease-in (4)** — разгон: медленно стартует, к концу движется быстрее.
- **ease-out (5)** — торможение: быстро стартует, к концу замедляется.
- **cubic in-out (2)** — S-кривая: плавный разгон в начале и плавное торможение
  в конце, симметрично.
- **catmull (3)** — плавные дуги: сплайн по 4 соседним кадрам, самое «мягкое»
  движение, проходящее через кадры без углов.

Сравнивай одновременно: hold заметно «дёргается», linear ровный, ease-in и
ease-out — зеркальные по ощущению, in-out мягкий с обоих концов, catmull —
самый гладкий.

## 4. Чек «легаси не сломан»

Требование: **старый пак без правок обязан анимироваться как раньше.**

Почему это работает (по коду `objcubed.js` ~2904–2912): easing хранится 4 битами,
разложенными по служебным битам PNG-текстуры данных. Старые сборки писали в эти
биты **0**. Новый ридер читает те же биты как индекс easing → у любого легаси-PNG
получается **easing = 0**, то есть режим hold, ровно как раньше (побитно
идентичное декодирование). Per-frame easing был отклонён именно ради этой
совместимости.

Практическая проверка:

1. Возьми ресурспак, экспортированный **старой** версией плагина (до добавления
   easing), НЕ переэкспортируя и НЕ трогая его файлы.
2. Загрузи его в игре, покажи модель, запусти анимацию.
3. Движение должно совпадать с тем, что было раньше (hold-поведение по кадрам).
   Никаких новых сглаживаний, никаких изменений тайминга.
4. Дополнительно: свежий экспорт с «Плавность = Нет (удержание)» (easing = 0)
   должен выглядеть **идентично** старому паку — это подтверждает, что дефолт
   не изменил поведение.

Если легаси-пак вдруг стал сглаживаться сам по себе — это регресс совместимости.
