# IK-анимация в Blockbench — практический гайд

> Практическое руководство для мапмейкеров, которые собирают арматуры с мешами и
> гоняют результат через **obj³ (objcubed)**. Официальная документация Blockbench
> факт наличия IK упоминает, но *как им пользоваться* — не объясняет. Этот файл
> закрывает дыру: точные клики, подводные камни и честные ограничения.
>
> Всё ниже проверено по исходникам Blockbench (`js/outliner/types/null_object.js`,
> `js/animations/timeline_animators.js` → `NullObjectAnimator.displayIK`,
> `js/animations/animation.js` → `Animation.sampleIK` / action `bake_ik_animation`).
> Терминология и названия пунктов меню — как в актуальном en.json.

## 0. Как IK устроен в Blockbench (модель, которую надо держать в голове)

Blockbench не «привязывает» кость к цели. Механика такая:

- **Null Object** — невидимый пустой объект. У него в режиме анимации есть поля
  `ik_target` (**Set IK Target**) и `ik_source` (**Set IK Root**), а также флаг
  `lock_ik_target_rotation`. У аниматора Null Object канал ровно один — **position**
  (`max_data_points: 2`). Ни вращения, ни масштаба у цели нет — это важно.
- Ты анимируешь **позицию Null Object**. На каждом кадре Blockbench строит цепочку
  костей и решает FABRIK-солвером (библиотека FIK, `FIK.Chain3D` / `FIK.Bone3D`),
  чтобы **конец цепочки дотянулся до Null Object**.
- Цепочка строится так: солвер берёт кость `ik_target`, идёт **вверх по родителям**
  до кости `ik_source` (если Root не задан — до **родителя самого Null Object**).
  Все кости между Root и Target включительно и есть цепь. **Длина цепи = глубина
  этой иерархии.** Отдельного поля «chain length» в UI нет — длину задаёшь тем,
  какой Root выбрал.
- Результат солвера применяется как **прибавка к вращению костей**
  (`bone.mesh.rotation += solved`) поверх уже посчитанной позы. Отсюда следует
  главный практический вывод: **стартовая поза костей определяет, в какую сторону
  сгибается сустав** (см. §3). Pole-target'а нет.

Жёсткое правило солвера (из `displayIK`):

```
if (!target.isChildOf(source) && source != 'root') return;
```

**Если Target не является потомком Root — IK молча ничего не делает.** Никакой
ошибки, просто цепь не шевелится. Это причина №1 «почему IK не работает» (см. §5).

## 1. Подготовка арматуры (что критично ДО того, как трогать IK)

IK считается по **мировым позициям пивотов** костей и по их **стартовому вращению**.
Поэтому 80% проблем лечатся здесь, а не в анимации.

### 1.1 Иерархия групп-костей

- Каждая кость — это **Group** (папка в Outliner). Меш/кубы кладутся **внутрь**
  группы и двигаются вместе с ней как жёсткий кусок.
- Строй нормальную родительскую цепочку: `hip → thigh → shin → foot`. IK пойдёт
  вверх по этим родителям, так что иерархия обязана быть непрерывной. Если между
  `thigh` и `shin` затесалась лишняя группа-обёртка — она тоже станет звеном цепи.
- Тип цели/корня:
  - **IK Target** может быть **Group**, **ArmatureBone** или **Locator**.
  - **IK Root** — только **Group** или **ArmatureBone** (локатор корнем быть не может).

### 1.2 Пивоты (Pivot Point) — самое важное

Солвер строит «кости» FABRIK по **мировым позициям пивотов** соседних групп
(`bone.mesh.getWorldPosition`), а направление отдыха — по разнице `origin` соседей.
Значит:

- **Пивот каждой группы должен стоять точно в суставе** — там, где кость реально
  вращается (пивот `thigh` = тазобедренный, пивот `shin` = колено, пивот `foot` =
  щиколотка). Пивот не на суставе → рычаг посчитается криво, колено «поедет».
- Пивоты соседних костей **не должны совпадать** в одной точке. Нулевая длина
  звена = вырожденная кость = дёрганье/NaN в солвере.
- Кость `ik_target` — это **последняя** кость, до чьего *пивота* тянется конец цепи.
  То есть цель — это стопа/кисть, а сам Null Object — точка, куда её тянут.

Проверка: включи отображение пивотов, пройди по цепочке сверху вниз — каждый
оранжевый крестик должен сидеть в анатомическом суставе.

### 1.3 Привязка мешей

- Меши внутри группы двигаются **как жёсткое целое** вместе с ней. При классическом
  group-IK **весов вершин нет** — на сгибе сустава два меша-звена просто
  пересекаются/расходятся (см. §6). Это норма для Minecraft-геометрии.
- Практика: делай **перекрытие геометрии в суставе** (нижний конец бедра и верхний
  конец голени слегка входят друг в друга цилиндром), чтобы на изгибе не появлялась
  щель.
- Если нужна именно гладкая деформация с весами — это уже путь **Armature /
  ArmatureBone** (`bone_weights`), а не group-IK. obj³ такое умеет
  («Armature & bone skinning»), но комбинация «арматура-веса + IK» — экспериментальная,
  держи её отдельно от простого group-IK.

### 1.4 Формат проекта

IK-поля (`ik_target`, `ik_source`) видны только когда `Format.animation_mode`
активен, т.е. в форматах с анимацией (Generic Model и т.п.). На чистом блочном
формате без анимации полей IK не будет.

## 2. Создание Null Object и назначение IK-цели

### 2.1 Создать Null Object

1. Перейди в **Edit**-режим (вкладка сверху).
2. Выдели в Outliner **кость-родитель цепи** — ту, что двигаться **не** должна
   (например `hip`). Новый объект появится её потомком.
3. Меню **Edit → Add Null Object** (или кнопка добавления в тулбаре Outliner).
   Появится маленький «крестик» — это и есть Null Object.
4. Поставь Null Object туда, где должен быть **конец цепи в стартовой позе** —
   обычно ровно на пивот стопы/кисти (цели). Позицию правь в панели свойств
   элемента.

> Важно: где стоит Null Object в **нулевом кадре**, туда цель и «прилипнет» на
> старте. Ставь его в анатомически корректную стартовую точку — это заодно задаёт
> опорную позу для §3.

### 2.2 Назначить IK Target и (опционально) IK Root

Всё это — **правый клик по Null Object** в Outliner (или ПКМ в 3D-вьюпорте по
самому крестику). В контекстном меню есть блок IK:

- **Set IK Target** — открывает список костей (поиск работает). Выбери кость на
  **конце** цепи (стопа/кисть/кончик хвоста). У выбранной строки появится галочка
  «(✔)». Это поле `ik_target`.
  Подсказка из Blockbench: *«Select the target bone that should be moved by this
  null object via Inverse Kinematics»*.
- **Set IK Root** — задаёт **первую (корневую) кость цепи**. Это и есть аналог
  «chain length»: чем «выше» корень, тем длиннее цепь.
  Подсказка: *«Select the root bone of the chain that should be moved… via IK»*.
  - **Если Root не задавать** — корнем автоматически становится **родитель Null
    Object** (та кость, к которой ты его прицепил в §2.1). Для большинства
    двух-трёхзвенных ног/рук этого достаточно: прицепил Null к `hip`, Target = `foot`
    → цепь `thigh → shin → foot` собирается сама.
  - **Задавай Root явно**, когда Null Object висит не там, где начинается цепь, или
    когда надо укоротить/удлинить цепь независимо от точки крепления.
- **Lock IK Target Rotation** (галочка-тумблер) — фиксирует **мировое вращение
  целевой кости**. Классика: стопа остаётся параллельной полу, пока нога сгибается.
  Работает только если Target — Group/ArmatureBone (для Locator смысла нет).

**Ключевое условие корректной цепи:** `ik_target` обязан быть **потомком** `ik_source`
(или родителя Null Object). Target = `foot`, Root = `thigh` — ок. Target = `foot`,
Root = кость из другой ноги — цепь пустая, IK не сработает.

## 3. Анимация: что можно, что нельзя, и как рулить изгибом БЕЗ pole-target

### 3.1 Что анимируем

1. Переключись в **Animate**-режим, создай анимацию.
2. В Outliner выдели **Null Object** → он появится дорожкой на таймлайне с
   **единственным каналом Position**.
3. Ставь кейфреймы **позиции Null Object**. Двигаешь крестик — цепь костей тянется
   за ним на каждом кадре. Всё.

### 3.2 Что делать НЕЛЬЗЯ

- **Не вращай руками кости внутри IK-цепи по кейфреймам.** Солвер применяет своё
  вращение *поверх* твоего (`rotation += solved`), результат подерётся и «поплывёт».
  Кости цепи (`thigh`, `shin`) в IK-анимации — не трогаешь; ты дирижируешь только
  целью.
- Не анимируй scale/rotation самого Null Object — у него канал только position,
  остальное игнорируется.
- Родительскую кость выше Root (например `hip`/таз) вращать **можно** — она вне
  цепи, и IK честно доработает под её новое положение.

### 3.3 Контроль изгиба без pole-target (главные трюки)

Pole-target'а в Blockbench нет. Направление сгиба определяется **стартовой
конфигурацией цепи**. Практические приёмы:

1. **Пред-сгиб в стартовой позе (самый надёжный).** В Edit-режиме чуть согни
   сустав в нужную сторону *в состоянии покоя*: колено — слегка вперёд, локоть —
   слегка назад. Даже 2–5° достаточно, чтобы задать солверу «подсказку», куда
   ломаться. Прямая (полностью выпрямленная, 180°) цепь — вырожденный случай:
   солвер сам не знает сторону и может вывернуть сустав.
   Технически это работает потому, что IK строит цепь из **текущего вращения
   костей** и прибавляет решение к нему.
2. **Микро-смещение цели.** Если на каком-то кадре сустав «щёлкает» на другую
   сторону, сдвинь Null Object на доли пикселя (или добавь промежуточный кейфрейм),
   чтобы цепь не проходила через идеально выпрямленное состояние.
3. **Порядок ключевых поз.** Прокладывай движение так, чтобы между двумя позами
   цепь **не распрямлялась в ноль** и не проходила через линию «корень–цель». Через
   распрямление — там и происходит переворот колена.
4. **Разбиение длинной цепи.** Одну длинную цепь (например хвост из 8 сегментов)
   лучше разбить на 2 Null Object'а с более короткими цепями (Set IK Root у второго
   ставишь в середину хвоста). Короткие цепи стабильнее и предсказуемее по изгибу,
   плюс получаешь раздельный контроль двух участков.
5. **Lock IK Target Rotation** — включай для стоп/кистей, которые должны сохранять
   ориентацию (стоять на полу), иначе они будут «доворачиваться» вслед за голенью.

## 4. Запекание IK и экспорт в obj³

obj³ **бэйкает анимацию покадрово** в кодированную PNG-текстуру. Кодировщик читает
**обычные кейфреймы вращения костей**, а не «живой» IK-превью. Поэтому порядок такой:

### 4.1 Сначала — запечь IK в кейфреймы вращения

1. В **Animate**-режиме выдели нужную анимацию.
2. Выполни действие **Bake Inverse Kinematics** (id `bake_ik_animation`, иконка-шестерёнка
   `precision_manufacturing`). Найти можно через строку поиска действий или в меню
   Animation; пункт активен только когда в проекте есть Null Object с заданным
   IK Target.
   Описание из Blockbench: *«Bake the rotations applied by inverse kinematics into
   the selected animation»*.
3. Что произойдёт: Blockbench прогонит `sampleIK` по всей длине анимации и создаст
   **rotation-кейфреймы на костях цепи** (`thigh`, `shin`, …). Значения округляются
   до 4 знаков, одинаковые соседние кадры выкидываются.

**Частота запекания** = параметр **Snapping** самой анимации (кадров/сек, в свойствах
анимации; клампится 10–500), а не глобальный `Animation Sample Rate` — тот влияет
только на форматы, экспортирующие кривые нативно (glTF/Bedrock). Хочешь плотнее
дискретизацию IK → **подними Snapping анимации перед бейком**.

> После бейка на костях цепи появятся явные ключи вращения. С этого момента Null
> Object для рендера больше не нужен, но **не удаляй его** и **сохрани `.bbmodel`**,
> если планируешь править движение — повторный бейк перезапишет позу заново.

### 4.2 Проверка перед экспортом

- Прокрути таймлайн: цепь должна повторять движение цели **без** живого IK (т.е.
  чисто на запечённых ключах). Если движение пропало — бейк не применился (проверь,
  что Target задан и Target — потомок Root).
- Убедись, что на костях цепи нет **дублей** твоих ручных вращений поверх
  запечённых (см. §3.2) — иначе будет двойное вращение.

### 4.3 Экспорт

1. Вернись в **Edit**-режим (obj³ намеренно блокирует экспорт из Display/Animate,
   чтобы поза вкладки не запеклась в статическую геометрию; каноническое состояние —
   Edit).
2. **File → Export → Export as obj³…**.
3. В диалоге экспорта, секция **Animation**: выбери анимацию, выставь **FPS** и
   диапазон времени. Именно здесь obj³ решает, сколько кадров запечь в текстуру —
   ставь FPS согласованно со Snapping анимации, чтобы не терять/не дублировать
   промежуточные позы.
4. **Export** → получаешь PNG (закодированная модель) + JSON (модель Minecraft).
   При включённой анимации доступна генерация датапака (play/stop/play_once/…).

### 4.4 Что проверить в результате

- Число кадров в кодированной текстуре соответствует `длительность × FPS`.
- В игре сгиб суставов совпадает с превью Blockbench (если разошёлся — почти всегда
  дело в §5).
- Если экспорт как **equipment/armor**: пивоты групп стоят на костях тела (плечо/бедро),
  теги body-part проставлены (§ README, «Armor / equipment export»).

## 5. Частые проблемы и лечение

| Симптом | Причина | Лечение |
|---|---|---|
| **IK вообще не влияет на кости** | `ik_target` не потомок `ik_source`/родителя Null Object → срабатывает `if (!target.isChildOf(source)) return` | Перепроверь иерархию Outliner. Target должен лежать *под* Root в дереве. Если Root не задан — Null Object должен висеть на кости *над* всей цепью |
| **IK не активен / нет полей** | Проект не в анимационном формате, или ты в Edit-режиме смотришь дорожки | Формат с `animation_mode`; поля IK видны в режиме Animate |
| **Цепь дёргается / трясётся** | Совпадающие пивоты (звено нулевой длины) или цель проходит через полностью выпрямлённую цепь | Разведи пивоты по суставам; добавь пред-сгиб (§3.3.1); микро-сместь цель (§3.3.2) |
| **Колено/локоть выворачивается не туда** | Стартовая цепь идеально прямая — солвер не знает сторону | Согни сустав на 2–5° в покое в нужную сторону (§3.3.1); не веди цель через линию «корень–цель» |
| **Сустав щёлкает на середине движения** | Цепь на каком-то кадре распрямляется в ноль и «переворачивается» | Проложи траекторию цели в обход распрямления; добавь промежуточный кейфрейм |
| **Стопа/кисть болтается, не держит пол** | Не включён Lock IK Target Rotation | ПКМ по Null Object → **Lock IK Target Rotation** |
| **После бейка кость крутится вдвое сильнее** | Поверх IK остались ручные rotation-кейфреймы на костях цепи | Убери ручные ключи с костей цепи; цепью рулит только цель |
| **В obj³ анимация статична / IK не виден** | Экспорт без бейка: кодировщик читает ключи, а живой IK-превью не запечён | Сначала **Bake Inverse Kinematics**, потом экспорт |
| **Грубая, «ступенчатая» IK-анимация** | Низкий Snapping анимации при бейке | Подними **Snapping** анимации перед бейком; согласуй с FPS в диалоге obj³ |
| **Щель в суставе на изгибе** | Нет весов вершин: два жёстких меша расходятся | Сделай перекрытие геометрии в суставе (§1.3) или переходи на Armature-скиннинг |

Диагностический порядок при «IK не работает»: **(1)** формат анимационный? →
**(2)** Target задан и это потомок Root? → **(3)** пивоты на суставах и не
совпадают? → **(4)** нет ли ручных вращений на цепи? → **(5)** запёк ли IK перед
экспортом?

## 6. Ограничения — честно

Чтобы не искать несуществующие кнопки:

- **Нет pole-target.** Направление изгиба задаётся только стартовой позой костей и
  траекторией цели (§3.3). Отдельного «указателя колена» нет.
- **У цели только канал position.** Null Object нельзя вращать/масштабировать по
  кейфреймам — солвер это игнорирует (`max_data_points: 2`, только position).
  Ориентацию конечной кости даёт лишь тумблер **Lock IK Target Rotation** (вкл/выкл),
  без анимируемого угла.
- **Нет весов вершин в classic group-IK.** Кости — это Group'ы, меши внутри
  двигаются жёстко. На сгибе суставы пересекаются/расходятся; гладкой деформации
  нет. Веса вершин существуют только в отдельной системе **Armature/ArmatureBone**
  (`bone_weights`), и это другой воркфлоу.
- **«Chain length» нет как числового поля.** Длина цепи = глубина иерархии между
  **IK Root** и **IK Target**. Управляешь ею выбором Root (**Set IK Root**), а не
  числом.
- **IK живёт только в превью, пока не запечён.** В файл/экспорт он попадает лишь
  через **Bake Inverse Kinematics** (rotation-кейфреймы). obj³ и другие форматы
  читают именно запечённые ключи, а не сам солвер.
- **Жёсткое условие иерархии.** Target обязан быть потомком Root — иначе тишина,
  без предупреждений.
- **Один солвер = одна цепь на Null Object.** Для нескольких конечностей — несколько
  Null Object'ов; для длинной цепи стабильнее разбить на несколько коротких.

### Короткий чек-лист «сделать ногу с IK и загнать в obj³»

1. Иерархия `hip → thigh → shin → foot`, пивоты точно в суставах, колено пред-согнуто на ~3°.
2. Выдели `hip` → **Edit → Add Null Object**, поставь крестик на пивот `foot`.
3. ПКМ по Null Object → **Set IK Target** = `foot`. (Root оставь пустым — возьмётся `hip`.)
4. ПКМ → **Lock IK Target Rotation** (чтобы стопа не заваливалась).
5. **Animate** → анимируй **position** Null Object по кейфреймам.
6. **Bake Inverse Kinematics** (подняв Snapping анимации до нужного FPS).
7. **Edit** → **File → Export → Export as obj³…**, секция Animation: та же анимация, тот же FPS, диапазон.
8. Export → проверь число кадров и совпадение сгиба с превью.
