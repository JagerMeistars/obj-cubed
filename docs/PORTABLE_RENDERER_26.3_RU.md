# Экспериментальный рендерер без subgroup для Minecraft 26.3

Этот вариант работает средствами ванильного resource pack. Клиентский мод не нужен.
Он не использует subgroup, ballot, shuffle, int64, compute или geometry shader.
Целевой интерфейс — GLSL 3.30, 64 компонента между vertex и fragment shader.
Minecraft 26.3 по-прежнему компилирует его через ShaderC/SPIR-V и переводит обратно
в GLSL для OpenGL; тот же исходник предназначен и для Vulkan.

## Устройство

Обычные модели проходят обычную отрисовку. Для модели obj³ четыре исходные вершины
передают свою плоскость через интерполируемые каналы. Пиксельный шейдер восстанавливает
положение, поворот и масштаб этой плоскости, пересекает её настоящую геометрию лучом
и записывает глубину поверхности. Ему не требуется читать другую GPU-инвокацию.

Для предметов исходный декодер геометрии и анимации выполняется в vertex shader
на канонической плоскости; реальный поворот и масштаб применяются после переноса.
Подготовленная броня AS1 декодирует кадр и UV в vertex shader, а fragment shader
восстанавливает только систему координат носителя. Для этого каждый слой хранит
одну направленную грань; остальные UV-прямоугольники ванильной брони схлопываются
в линии до растеризации. Первый исходный слой сохраняется: Minecraft добавляет
зачарование только на него. Он использует общий расчёт на грань и границы AB1. Сохранены исходные формулы анимации,
привязки частей брони, ручного кадра и управления через цвет.

Совместимые непрозрачные грани брони дополнительно объединяются в AS2: один
северный носитель на часть тела и дерево поиска по исходной геометрии. Группируются
только одинаковые материалы, часы анимации, параметры слоя и цветовые текстуры.
Прозрачные грани сохраняют AS1. Первый исходный слой остаётся отдельным для glint.
UV и полосы анимации текстуры выбираются после нахождения грани, поэтому разные
полосы внутри одного материала сохраняют собственную анимацию.

Для непрозрачных предметов доступна конвертация в BVH: один носитель на модель,
дерево границ всех кадров в той же PNG и поиск ближайшей видимой грани. Сами исходные
вершины, индексы и UV остаются прежними. Дерево учитывает контрольные точки кубической
интерполяции. Для анимации дополнительно записываются сжатые границы текущего
сегмента (BF1), чтобы не обходить весь объём движения на каждом кадре. После
изменения easing в PNG конвертацию нужно повторить. Прозрачные модели и модели с неодинаковыми параметрами граней, например
разным `light_emission`, сохраняют отрисовку отдельных граней.

Во всех фазах OIT используется глубина найденной поверхности. Глубина экранной
плоскости не подменяет поверхность при проверке перекрытия миром.

## Сборка

Готовый пакет шейдеров можно положить выше экспортированных моделей в списке RP.
Экспортёр 26.3 нужен для явных маркеров first-person; старые PNG сохраняют старую
эвристику определения контекста.

Сборка из репозитория, где `VANILLA` — извлечённый каталог шейдеров клиента 26.3:

```sh
node tools/build-portable-pack.mjs objcubed NEW_PORTABLE_PACK VANILLA/assets/minecraft/shaders
node tools/prepare-portable-models.mjs EXPORTED_MODEL_PACK NEW_PORTABLE_MODEL_PACK
```

Команда подготовки моделей добавляет BVH к подходящим непрозрачным предметам
и таблицы границ AB1 к броне, затем переводит её последующие слои в AS1
и объединяет подходящие непрозрачные группы в AS2. Каждая граница брони охватывает все кадры и
контрольные точки интерполяции; это позволяет отсечь луч до дорогого декодирования
геометрии. Пустые торцы humanoid также отбрасываются заранее.

Обе команды создают новый каталог. Исходные пакеты остаются прежними. Результат BVH
нужно использовать вместе с portable-шейдерами: обычный subgroup-рендерер не рисует
модели с одним носителем целиком. Конвертер записывает `portable-bvh-manifest.json`
с преобразованными и пропущенными моделями и результатами проверки лучей,
а `portable-armor-bounds-manifest.json` — с обработанными слоями брони.
`portable-armor-vertices-manifest.json` и `portable-armor-bvh-manifest.json`
сохраняют соответствие исходных и новых граней.
AS1 сохраняет все кадры, позиции, UV, материалы и целевые части тела; число
equipment layers увеличивается, а геометрические таблицы в каждой PNG сокращаются
до одной грани. AS2 затем сокращает число слоёв для совместимых непрозрачных
групп. Первый слой сохраняется для штатного glint. Для сложной брони
полная подготовка существенна: первоначальный вариант
вызвал сброс GPU на AMD при 18 слоях; одних границ AB1 тоже оказалось недостаточно. Старые PNG читаются, но могут быть слишком
дорогими для такого пути.

## Допустимые приближения первого варианта

- Положение плоскости восстанавливается с конечной точностью. Измеренная ошибка
  переноса при координатах до 4096 — до 0,000982 при 1080p и 0,00293 при 4K.
- Пользовательские поверхности рисуются с обеих сторон. Если две половины одной
  неплоской прозрачной грани перекрываются, сохраняется ближайшая половина.
  Разные прозрачные грани по-прежнему участвуют в отдельных проходах OIT.
- Свет и оттенок пользовательской грани передаются с точностью 8 бит на канал;
  независимые значения освещения четырёх углов заменены одним значением на грань.
- Особый блеск предметов восстановлен по формуле Minecraft для стандартных
  северных плоскостей, создаваемых экспортёром. Произвольная ручная переделка
  их геометрии может потребовать иной формулы.
- Копланарные непрозрачные наложения могут зависеть от порядка отрисовки.
  AS2 сохраняет порядок исходных граней при равной вычисленной глубине;
  совпадающая геометрия с разными UV исключается из объединения.
- Путь отдельных граней дорогой: число граней и разрешение существенно влияют
  на скорость. BVH применяется только там, где объединение граней сохраняет
  их материал и непрозрачность.

Подтверждённые проверки и ограничения аппаратной проверки фиксируются отдельно
в отчёте поставки. Успешная компиляция не означает, что модель проверена в игре.
