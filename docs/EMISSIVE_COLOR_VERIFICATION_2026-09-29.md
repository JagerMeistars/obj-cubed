# obj³ 0.8.3: свечение и color behavior

## Исправления

Свечение сопоставлялось с именем элемента без учёта регистра. Поэтому одноимённые
кубы/меши получали максимальный уровень свечения среди всех элементов с таким
именем. Теперь на время OBJ-экспорта каждый элемент получает уникальный токен с
его собственным уровнем. Исходные имена восстанавливаются и после успешного
экспорта, и при ошибке. Соглашения имён `*_e` и `emissive*` сохранены.

В color behavior любой канал `direct` заменял результат `overlay` или `hurt`
соседних каналов. Теперь тинт, оттенок и вспышка перемножаются. Применение цвета
вынесено из проверки `noshadow`: «Без тени» не отменяет выбранные цвета.

Эти ошибки цвета существовали и в релизе 26.2 (`41bf938`): до исправления все
1390 GPU-случаев совпадали с его декодером и освещением попиксельно.

## Проверки

- **299 автоматических тестов.** Среди них экспорт одноимённых cube/Mesh с разными
  уровнями, повторное включение/выключение свечения, восстановление имён после
  ошибки и 250 PNG с 125 сочетаниями RGB при двух наборах соседних флагов.
- Проверены реальные методы диалога: переключение каналов, сохранение настроек,
  повторное открытие, принудительный режим времени для датапака и возврат назад.
  Это Node-проверка, без интерфейса Blockbench.
- **83/83 программ**: ShaderC → SPIR-V → SPIRV-Cross → GPU compile/link, включая
  варианты OIT, glint, освещения, item/entity/block/terrain.
- **1390 GPU-рендеров, 5568 проверок.** Все 125 сочетаний пяти сохранённых режимов
  (`direct`, `time`, `scale`, `overlay`, `hurt`), освещённый/полнояркий режим,
  нулевые/белые значения и границы управления анимацией. `scale` — сохранённый
  legacy-режим; обычные кнопки интерфейса циклически переключают остальные четыре.
- Независимый CPU-эталон вычисляет HSV × тинт × вспышку, допуск — 1/255 на канал.
  До исправления было 360 ошибок цвета, после — 0. Покрытие пикселей, положение,
  масштаб и выбор кадров всех 1390 случаев сохранены относительно исходного кода.
- Исполнены настоящий JSON-десериализатор и `VertexConsumer.putBakedQuad` из
  клиента Minecraft 26.3: уровни граней `0 → 15 → 0 → 7 → 0` дают UV2
  `0 → 240 → 0 → 112 → 0`. Свет одной грани не переносится на следующую.
  Полный model bake между этими API не исполнялся; промежуточный путь проверен
  по байткоду.
- Источник окраски проверен через настоящий `ItemTintSources.CODEC` и
  `Potion` tint source Minecraft 26.3: все узлы экспортированного selector
  получают RGB `(80,144,208)` из `potion_contents.custom_color` предмета
  `iron_ingot`; без компонента возвращается белый. `default:-1` допустим.
  Это CPU-проверка компонентов на тестовом ItemStack без загрузки мира;
  прототип его holder задан пустым вручную вместо стадии загрузки datapack.

GPU: NVIDIA RTX 4060 Ti, драйвер 595.71, невидимый OpenGL-контекст, 128×128 RGBA8.
Проверен фактический вывод шейдеров на GPU; это не игровой прогон, замер FPS,
рендер Vulkan или OIT. Матрица OIT выше подтверждает компиляцию, не изображение.
Полный путь от игровой команды до предмета на экране и UI Blockbench в этот
прогон не входят. ComputerUse не применялся.

## Область действия RGB

У item/entity моделей выбранные каналы управляют цветом, временем и масштабом.
У equipment-броней RGB остаётся словом управления анимацией, независимо от режима
color behavior. Block/terrain не декодируют эти режимы. Эти ограничения исходного
рендера сохранены; соответствующие GPU-случаи совпадают с релизом 26.2.
Плагин теперь явно поясняет отличие надетой брони от экспортируемого предмета.

Для применения исправления обновите плагин и ресурс-пак шейдеров, переэкспортируйте
модели со свечением и перезагрузите ресурсы через F3+T.

Воспроизводимые GPU-команды: `tools/render-tester/README.md`. Локальные результаты:
`audit/2026-09-29/color-behavior-{before,after}/`, `emissive-color-matrix/`,
`emission-vertex-probe.json`, `tint-input-probe.json`, `emissive-color-unit-tests.log`.
