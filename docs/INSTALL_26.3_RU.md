# obj³ для Minecraft 26.3 — кандидат для проверки

**Задача поддержки Intel iGPU и Apple M целиком ещё не решена.**
Здесь есть перенос на 26.3 и отдельный обход ошибки OpenGL-компиляции.
В обоих пакетах остаётся чтение соседних вершин GPU. Отдельный эксперимент без
subgroup пока проверяет только передачу данных, а не рисование моделей.

## Установка

1. В Blockbench откройте File → Plugins → Load Plugin from File и выберите
   `objcubed.js` из этого комплекта.
2. Выберите **один** пакет шейдеров и положите его ZIP в `resourcepacks`:
   - `objcubed-26.3-default.zip`: основной вариант с KHR basic/ballot.
     Компиляция проверена на NVIDIA; на тестовой AMD его OpenGL-путь блокирует
     ошибка транслятора Minecraft. Vulkan требует vertex-stage subgroup.
   - `objcubed-26.3-opengl.zip`: экспериментальный вариант для **рендерера OpenGL**,
     использующий `GL_ARB_shader_ballot` и `GL_ARB_gpu_shader_int64`.
     Не используйте его с рендерером Vulkan. Он не предназначен для Apple M.
3. Включите выбранный пакет в Minecraft Java **26.3**. Одновременно включать
   оба варианта не нужно: они заменяют одни и те же шейдеры.
4. Повторно экспортируйте свои модели, PNG и datapack новым плагином. Это нужно
   для явных маркеров правой/левой руки и актуального формата datapack.
5. Добавьте полученные assets в свой пакет моделей, как при обычном экспорте obj³.

Старые PNG сохраняют прежнее эвристическое определение руки, которое ненадёжно
в 26.3. Копирование только новых шейдеров не обновляет эти PNG.

Оригинальные демонстрационные assets из архива 26.2 сохранены отдельно в
`examples-26.2/` комплекта. Они не включены автоматически в новые пакеты,
поскольку не были повторно экспортированы с новыми маркерами.

## Что подтверждено

Перенос интерфейсов шейдеров, форматов пакетов и first-person маркеров проверен
автоматическими тестами. Варианты компиляции и отдельные операции чтения вершин
проверены на доступных NVIDIA GTX 1650 и AMD Renoir. Полного игрового прогона
ванильного клиента и тестов на Intel/Apple в этой работе не было.

OpenGL-вариант прошёл сравнение данных при обычной растеризации на обеих GPU:
по 1 248 вызовов отрисовки и 3 432 384 проверенных пикселя без ошибок. На AMD
аналогичный тест в режиме transform feedback провален: драйвер повторно исполняет
одну вершину в разных потоках. Этот известный предел проверки сохранён в отчёте;
успешную компиляцию и обычную растеризацию нельзя обобщать на все режимы драйвера.
